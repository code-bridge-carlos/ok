Endpoints de la API:
  - OpenCode Server local → Provider API (Anthropic/OpenAI/DeepSeek/etc)

═══════════════════════════════════════════════════════════════════════════════
  DETALLES TÉCNICOS
═══════════════════════════════════════════════════════════════════════════════

TEMPERATURA:
  - temperature: 1 (default) → respuestas más creativas/diversas
  - temperature: 0 → respuestas más deterministas/predictibles
  - OpenCode usa 1 por defecto, pero se puede configurar

MAX_TOKENS:
  - max_tokens: 8192 → límite de tokens en la respuesta
  - Si la respuesta es más larga, se trunca
  - Se puede configurar en opencode.json

HISTORIAL:
  - Cada request incluye TODOS los mensajes anteriores
  - El historial crece con cada tool_call
  - Ejemplo: Request 3 tiene 8 mensajes (system + user + 3 assistant + 3 tool)

TOOLS DISPONIBLES:
  - Se envían en CADA request (no se cachean)
  - El modelo los ve como "functions" disponibles
  - El modelo decide cuándo usarlos (no se lo obliga)

TOOL_CALLS:
  - El modelo responde con "tool_calls" en vez de "content"
  - OpenCode ejecuta la herramienta
  - El resultado se agrega como mensaje "tool"
  - Se repite el ciclo hasta que "finish_reason": "stop"

FINISH_REASONS:
  - "tool_calls" → el modelo quiere ejecutar algo
  - "stop" → el modelo terminó de responder
  - "length" → se alcanzó max_tokens
  - "content_filter" → el contenido fue filtrado

STREAMING:
  - "stream": false → recibe la respuesta completa de una vez
  - "stream": true → recibe tokens incrementalmente (SSE)
  - OpenCode puede usar ambos modos

Cuando una herramienta falla, OpenCode envía el error como resultado:

  tool_call: { "name": "read", "arguments": { "filePath": "/no/existe.py" } }
  
  Resultado:
  {
    "isError": true,
    "content": "Error: ENOENT: no such file or directory '/no/existe.py'"
  }

El modelo LLM recibe este error en el mensaje "tool" y decide:
  1. Informar al usuario: "No encontré el archivo..."
  2. Reintentar con otra ruta
  3. Usar glob para buscar el archivo
  4. Crear el archivo si no existe

El modelo TIENE acceso al error y puede reaccionar intelligentemente.
